# Тестирование 2.0.0-beta.1

Это отдельная предварительная версия установщика. Прежняя версия остаётся в [main](https://github.com/Necim1/Passwall2-install/tree/main). Бета не заменяет её автоматически.

## Что изменилось

- Установка выполняется на самом OpenWrt. Windows больше не обязательна; PowerShell передаёт проект по SSH и открывает то же меню.
- Архитектура и пакетный менеджер определяются автоматически: APK и IPK, ARM/ARM64, MIPS/MIPSel, x86_64 при наличии подходящих пакетов PassWall2.
- По свободному месту выбирается обычный пакет Xray или сжатый бинарник UPX. Настройки RAM и zram выбираются отдельно; существующий zram не перезапускается.
- Можно вставить одну VLESS/VMess/Trojan/SS-ссылку или HTTPS-подписку, выбрать серверы и исключить лимитные. Исключения сохраняются по точному названию после обновления подписки.
- Добавлены проверки SHA-256, потоковый выбор нужных пакетов, бэкапы и попытка восстановления настроек/старого Xray после ошибки.

## На чём пробовать

Нужен OpenWrt 24.10+ с firewall4/nftables, root SSH и минимум 128 МиБ физической RAM. Под Raspberry Pi и x86 здесь подразумевается именно OpenWrt. Для тесного flash или staging может потребоваться USB/extroot. Установщик не переразмечает flash, не меняет загрузчик и не обновляет прошивку.

Проверки в CI используют подмены OpenWrt-команд. Установку на все физические модели, соединение с вашим сервером и устойчивость под нагрузкой они не доказывают. Бета предназначена для проверки на тестовом устройстве с возможностью восстановления доступа. Подробности: [TESTING.md](TESTING.md).

## Установка по SSH

Команды ниже скачивают конкретную бету и сверяют SHA-256 перед распаковкой:

```sh
cd /tmp &&
wget -O Passwall2-install-2.0.0-beta.1.tar.gz https://github.com/Necim1/Passwall2-install/releases/download/v2.0.0-beta.1/Passwall2-install-2.0.0-beta.1.tar.gz &&
wget -O Passwall2-install-2.0.0-beta.1.tar.gz.sha256 https://github.com/Necim1/Passwall2-install/releases/download/v2.0.0-beta.1/Passwall2-install-2.0.0-beta.1.tar.gz.sha256 &&
sha256sum -c Passwall2-install-2.0.0-beta.1.tar.gz.sha256 &&
tar -xzf Passwall2-install-2.0.0-beta.1.tar.gz &&
cd Passwall2-install-2.0.0-beta.1 &&
sh install.sh check
```

Если проверка прошла, откройте меню:

```sh
sh install.sh
```

На чистом устройстве выбирайте **Install**. При существующей полноценной установке PassWall2 — **Update**: подписки и правила сохраняются, runtime Xray подбирается заново. Обновление может временно прервать проксирование. Конфликтующие включённые прокси-сервисы сначала нужно отключить самостоятельно.

Если в `/tmp` не хватает места, используйте staging на подключённом накопителе:

```sh
sh install.sh install --work-dir /mnt/usb --backup-dir /mnt/usb/pwsetup-backups
```

Из Windows можно скачать ZIP из Assets релиза, распаковать и запустить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Setup.ps1 -RouterHost 192.168.1.1
```

## Ссылка или подписка

В меню **Add server link / subscription** вставьте одну ссылку на сервер либо HTTPS-адрес подписки. Ввод скрыт. Для запуска сервера нужны рабочие параметры; тест запуска конфигурации не проверяет доступность самого VPN-сервера.

Выберите номера нужных узлов либо `all`. Если нужен только один сервер, оставьте выбранным только его. При обновлении подписки исключения действуют по точному названию; новый или переименованный сервер нужно проверить отдельно.

## Что проверить и куда написать

1. Создайте бэкап и скопируйте его с роутера до испытаний. Установщик также сохраняет бэкап в `/root/pwsetup-backups/` или заданном каталоге.
2. Проверьте открытие LuCI/SSH и интернет с LAN-клиента до и после установки.
3. Проверьте отдельно одну ссылку и подписку, выбор/исключение сервера, повторное обновление.
4. Запустите обычную длительную загрузку, проверьте остальные устройства и расход RAM/swap. Затем проверьте запуск после перезагрузки.
5. Оставьте [отчёт о тестировании](https://github.com/Necim1/Passwall2-install/issues/new?template=beta-test.yml): модель/ревизия, версия OpenWrt, архитектура, RAM, flash/extroot, этап и результат.

Для отчёта можно приложить вывод `sh install.sh status`. Не публикуйте URL подписки, UUID, пароли, ключи, полный UCI-конфиг или архив настроек.

При ошибке установщик пытается вернуть настройки, старый Xray и состояние сервиса. Версии пакетов и их база автоматически **не откатываются**. В сообщении указывается каталог восстановления; `/tmp` очищается при перезагрузке. Для возврата к прежней версии сохранённый бэкап может потребовать ручного восстановления/переустановки пакетов.
