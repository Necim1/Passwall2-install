# PassWall2 Router Setup

**Бета 2.0.0-beta.2:** [скачать предварительный релиз](https://github.com/Necim1/Passwall2-install/releases/tag/v2.0.0-beta.2) · [инструкция тестирования](BETA.md). Прежняя версия 1.x остаётся в [ветке main](https://github.com/Necim1/Passwall2-install/tree/main).

Установщик PassWall2 и Xray, который работает **на самом OpenWrt**. Windows не требуется. PowerShell остался необязательной оболочкой для передачи проекта по SSH.

Версия: **2.0.0-beta.2**. Это новая реализация. Офлайн-проверки и матрица выбора пакетов не заменяют установку и нагрузочный тест на настоящем устройстве. Для новой версии пока не заявляется проверка на физических Cudy, Raspberry Pi или MIPS-роутерах.

## Поддержка

- OpenWrt **24.10 и новее** с firewall4/nftables, `opkg`/IPK или `apk`/APK.
- Cudy, другие ARM/ARM64/MIPS-роутеры, Raspberry Pi **под OpenWrt**, x86_64 **под OpenWrt**.
- Архитектура берётся из OpenWrt, а не из названия модели. Нужен полный релиз PassWall2 для этой архитектуры и формата пакетов, с SHA-256 в GitHub API. Поддерживаются старые и новые имена архивов пакетов.
- Не менее **128 МиБ физической RAM**. Это нижний порог допуска, а не обещание скорости или отсутствия OOM при любой конфигурации.
- Достаточное место в writable-разделе; для тесного раздела есть режим compact. Если не помещаются даже остальные пакеты и GeoIP/GeoSite, нужен extroot/USB или другое устройство.
- Доступные репозитории OpenWrt, соответствующие установленной версии ядра. Kernel-пакеты не форсируются и прошивка не обновляется.
- Snapshot допускается только с `--allow-snapshot`. Старые версии OpenWrt и iptables/firewall3 не поддерживаются.

Raspberry Pi OS, Debian и обычная Windows не являются целевой ОС установки PassWall2/LuCI.

## Запуск

Скачайте и просмотрите проект на компьютере. Передайте **весь каталог** на роутер:

```sh
scp -O -r Passwall2-install root@192.168.1.1:/tmp/
ssh root@192.168.1.1
cd /tmp/Passwall2-install
sh install.sh check
sh install.sh
```

`check` только проверяет систему. Меню позволяет установить/обновить стек, восстановить его пакеты после обновления OpenWrt, добавить ссылку или подписку, выбрать серверы, применить профиль маршрутизации или создать бэкап. Модель вручную выбирать не нужно.

Имя каталога после распаковки может отличаться — используйте фактическое. Ветка разработки не является закреплённым релизом; для воспроизводимой установки используйте проверенный архив конкретного коммита/релиза. Установщик не требует `curl | sh` или `irm | iex`.

Вариант для Windows после скачивания проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Setup.ps1 -RouterHost 192.168.1.1
```

Оболочка использует OpenSSH и `tar`, передаёт проект и открывает меню на роутере. Она использует существующую SSH-аутентификацию; пароль не сохраняет. `bootstrap.ps1` теперь требует конкретный `-Commit` и ожидаемый `-Sha256` ZIP-архива, исполнять изменяемую ветку без проверки он не будет.

## Обычный и компактный Xray

```sh
sh install.sh install --storage auto
sh install.sh update --storage full
sh install.sh install --storage compact --work-dir /mnt/usb
```

В `auto` предпочтение отдаётся обычному пакету Xray. Перед выбором установщик измеряет извлечённые файлы, учитывает заменяемые файлы в overlay и оставляет запас 8 МиБ. Файлы из read-only `/rom` не считаются освобождаемым местом. При недостатке места готовится сжатый Xray через проверенный UPX для CPU роутера. Проверяются архив UPX, результат сжатия и запуск бинарника на устройстве.

UPX экономит место во flash. Настройки оперативной памяти выбираются **отдельно**:

| Физическая RAM, примерно | GOMEMLIMIT | GOGC | zram при отсутствии существующего zram |
| --- | --- | --- | --- |
| 128 МиБ | 32 MiB | 50 | 64 МиБ |
| 256 МиБ | 96 MiB | 50 | 128 МиБ |
| 512 МиБ | 192 MiB | 75 | не добавляется |
| 1 ГиБ и больше | стандартный режим Go | стандартный режим Go | не добавляется |

Пороги учитывают RAM, зарезервированную ядром. `GOMEMLIMIT` — мягкая цель Go, не жёсткий лимит RSS. Готовый runtime находится в `/usr/libexec/pwsetup/xray-runtime`, параметры — в `/etc/passwall2/pwsetup-runtime`. При запуске сохраняется `argv[0]`, который использует монитор PassWall2. Повторное применение маршрутизации сохраняет этот launcher.

Существующий zram не перезапускается. При необходимости новый zram запускается до подготовки Xray: память нужна и распаковке/сжатию. Перед UPX проверяется запас доступной RAM + свободного swap. `--zram off` запрещает добавление нового, не отключая имеющийся swap.

Пакеты выбираются из ZIP потоком через `bsdtar`; SHA-256 считается по **всему** исходному ZIP. До успешной проверки содержимое не устанавливается и не запускается. В staging не сохраняется весь архив с ненужными ядрами.

Для подготовки нужно не менее 64 МиБ свободного staging плюс место для сохранения предыдущего Xray. На слабом устройстве или при работающем Xray может понадобиться USB:

```sh
sh install.sh install --work-dir /mnt/usb --backup-dir /mnt/usb/pwsetup-backups
```

Установщик не переразмечает flash, не меняет U-Boot и не настраивает extroot автоматически.

## Один сервер или подписка

После установки выберите пункт **Add server link / subscription** и вставьте:

- `vless://`, включая параметры Reality/XHTTP;
- `vmess://`, `trojan://`, `ss://`;
- HTTPS-адрес подписки.

Определение типа автоматическое. Разбор выполняет установленный импортёр PassWall2. Неизвестный формат, несколько строк или импорт без Xray-узлов считаются ошибкой. Ссылка не передаётся через аргументы процесса, не выполняется как shell-код и не печатается в диагностике.

Для автоматизации используйте файл с правами `600`, чтобы секрет не попал в историю команд:

```sh
sh install.sh input --input-file /root/private-link.txt --yes
```

`--yes` включает все подходящие узлы с учётом сохранённых исключений. Без него после импорта можно выбрать номера серверов. Добавление сохраняет существующие узлы; если нужен только один, выберите только его. Обычное `install --yes` не запрашивает ссылку и оставляет проксирование выключенным.

Исключения сохраняются по **точному названию** сервера и действуют после смены ID при обновлении подписки. Одинаковые названия исключаются вместе; переименованный сервер считается новым. Пункт **Select nodes** позволяет изменить выбор. В балансировщик входят Xray-узлы подписок и одиночные ссылки, добавленные этим установщиком. Сторонние ручные узлы автоматически не подключаются.

Обновление подписок назначается на 05:00 одной задачей, последовательно: импорт → сборка балансировщика → проверка конфигурации/запуска. Обновление и установка используют общую блокировку. Выключенный в настройках или автозапуске PassWall2 задача не включает обратно. Ошибка с нулём узлов не активирует пустую конфигурацию. При недоступности подписки штатный импортёр может сохранить прежние узлы — это допустимо.

## Обновление и восстановление

### После обновления прошивки OpenWrt

Если настройки сохранились, а пакеты исчезли, выберите **7) Restore packages after OpenWrt upgrade (keep settings)** или выполните:

```sh
sh install.sh restore
# Если новая версия скрипта уже сохранена на устройстве:
sh /usr/libexec/pwsetup/app/install.sh restore
```

Восстанавливаются **PassWall2, Xray и их зависимости**. Наличие старого пакета PassWall2, init-скрипта и рабочего Xray не требуется. Архитектура, APK/IPK и официальные kernel-зависимости выбираются для текущей прошивки; старые APK/IPK и модули ядра не переносятся. Настройки не заменяются готовым шаблоном, подписка не импортируется заново, узлы, правила и исключения сохраняются. Путь к Xray обновляется на управляемый runtime.

Для этого при sysupgrade нужно сохранить настройки или заранее вернуть свой бэкап. В частности, нужен `/etc/config/passwall2`; исключения находятся в `/etc/config/pwsetup`. Если конфига нет или он повреждён, режим завершается до изменения пакетов и предлагает сначала восстановить настройки либо выбрать чистую установку.

Выключенный в конфиге прокси остаётся выключенным. Если init-скрипт сохранился, учитывается его прежний автозапуск. Если он утрачен при прошивке, автозапуск и запуск восстанавливаются по сохранённому `global.enabled`: при `1` включаются, при `0` не включаются. Перед изменениями создаётся новый бэкап, затем проверяются конфигурация и запуск.

Этот режим не восстанавливает OpenVPN или другие программы роутера. Для них нужна отдельная установка. Если после прошивки остался скрипт беты 1 без команды `restore`, скачайте свежую бету из Releases.

### Обновление уже установленных пакетов

```sh
sh install.sh update
# После первой успешной native-установки/миграции:
sh /usr/libexec/pwsetup/app/install.sh update
```

Перед изменениями создаётся `sysupgrade`-бэкап с SHA-256 в `/root/pwsetup-backups/`. Скопируйте его на компьютер: он содержит секреты. Если в пользовательском `/etc/sysupgrade.conf` перечислен Xray или другие большие файлы, они тоже попадут в архив и потребуют места. Перед остановкой PassWall2 скачиваются и проверяются release-пакеты и устанавливаются официальные зависимости. Для замены DNS на opkg обе версии dnsmasq заранее кешируются для восстановления без интернета.

При ошибке после начала изменения PassWall2 предпринимается восстановление предыдущей конфигурации, бинарника Xray, launcher и состояния сервиса. **Версии установленных пакетов и их база не откатываются автоматически.** Это не атомарная транзакция всей ОС. После частичной ошибки может понадобиться ручная переустановка пакетов; путь к бэкапу и приватному staging выводится в терминал. Перезагрузка стирает staging в `/tmp` и сохранённый там предыдущий Xray.

Обычное обновление сохраняет подписки, узлы и правила; выбирает новый runtime для ресурсов устройства. Профиль маршрутизации заменяется только явной командой `routing` или при новой установке. Активные конфликтующие прокси-сервисы блокируют установку. Автоматического удаления чужих сервисов нет.

Наличие процесса и успешный `xray run -test` подтверждают запуск и корректность конфигурации, **не доступность сервера или скорость**. После установки проверьте трафик с LAN-клиента и длительную загрузку, особенно на 128–256 МиБ RAM.

## Разработка и проверка

```sh
chmod +x tests/ash-runner.sh
PW_TEST_SHELL="$PWD/tests/ash-runner.sh" python3 tests/test_native.py
sh tests/CleanupPlan.sh
shellcheck -S error -s sh install.sh router/*.sh
```

Для Linux-проверок нужны Python 3, BusyBox, bsdtar и ShellCheck. Тесты работают в изолированном каталоге с подменами OpenWrt-команд. Проверяются матрица APK/IPK для 13 архитектур, выбор памяти/flash, контрольные суммы и повреждённый кеш, передача одиночных ссылок и подписок штатному импортёру, исключения и восстановление при ошибке. Они не эмулируют Xray-сервер или настоящее оборудование. [Все 23 теста пройдены под BusyBox ash](https://github.com/Necim1/Passwall2-install/actions/runs/43114462655); также пройдена проверка PowerShell 5.1.

Старые `router/install.sh`, `preflight.sh`, `check-existing.sh`, cleanup-скрипты и Windows helpers сохранены для совместимости с версией 1.x. Новый `Setup.ps1` их установочный сценарий не вызывает; новый вход — корневой `install.sh`.
